# Fadester for OBS — Requirements

Status: 2026-10-27. Approved by the operator on 2026-10-27 (decisions `D-1..D-4` recorded in Section 10).
Companion to [PLAN.md](PLAN.md) and [API-CONTRACT.md](API-CONTRACT.md); requirement IDs (`R-*`) and operator decisions (`D-*`) are referenced across the plan, test suite, mutation checks, and commit messages.

**Fadester for OBS** (`com.jbrick2070.fadester-for-obs.sdPlugin`) is an open-source Elgato Stream Deck + plugin written in TypeScript on the official Elgato Stream Deck SDK (`@elgato/streamdeck`) that connects directly to OBS Studio 33 over `obs-websocket` 5 and controls **Midi Fadester** via its `midi-fadester` vendor API ([API-CONTRACT.md](API-CONTRACT.md)). Phase 1 delivers the focused two-action launch set (**Fader** dial and **Auto-fade** key) with runtime-drawn Playlister-styled SVG cells (Fader cell with A-to-B gradient bar and soft-takeover arrow, T-bar cell with green Preview and red Program scene names, and Crossfade cell with optional 1–2 FPS `96 × 54` live `GetSourceScreenshot` thumbnails); extended graphics and performance actions from [GRAPHICS-NOTES.md](GRAPHICS-NOTES.md) and [IDEAS.md](IDEAS.md) are cataloged into Phases 2–4.

## 4. Connection Management, Status Sentences, and Reconnect Policy (`R-CON-*`)

| ID | Requirement |
|---|---|
| `R-CON-1` | **Global Connection Settings:** Stored once in Stream Deck global settings (`streamDeck.settings.getGlobalSettings` / `setGlobalSettings`) and editable from the shared Connection panel in every action's Property Inspector:<br>• `host`: string, default `"127.0.0.1"`<br>• `port`: integer `1..65535`, default `4455`<br>• `password`: string, default `""` |
| `R-CON-2` | **Four Exact Connection Status Sentences:** Every status or error shown to a person MUST be a clear sentence with the fix:<br>1. **Connected:** `"Connected: OBS <obsVersion>, Midi Fadester <version>"` (e.g., `"Connected: OBS 33.0.0, Midi Fadester 0.1.0"`, read from `GetVersion` and `get_state.version`).<br>2. **OBS Unreachable / WebSocket Off:** `"OBS is not running or the websocket is off (Tools > WebSocket Server Settings)"`<br>3. **Authentication Failed (`close code 4009`):** `"Wrong password. Check OBS Tools > WebSocket Server Settings > Show Connect Info."`<br>4. **Vendor Plugin Missing (`CallVendorRequest` status `600`):** `"Midi Fadester is not installed in OBS"` — displayed in the Property Inspector with a clickable link (`https://github.com/jbrick2070/midi-fadester/releases`) and on dial/key cells as a concise one-line reason. |
| `R-CON-3` | **Exponential Backoff & No Silent Retries on Wrong Password:**<br>• When a connection drops or fails due to network refusal (`ECONNREFUSED`, socket close, timeout), the client reconnects automatically with exponential backoff (`1 s → 2 s → 4 s → 8 s → max 10 s`).<br>• **When authentication fails (`obs-websocket` close code `4009`), automatic reconnect retries MUST STOP immediately** so a wrong password is never hidden behind silent retry loops or OBS log spam. Reconnection resumes only when the user edits `host`, `port`, or `password`, or clicks **Connect / Test**.<br>• When `GetVersion` succeeds but `midi-fadester` vendor requests return `600` (`ResourceNotFound`), automatic tight retries also pause until the user clicks **Connect / Test** or OBS restarts.<br>• When disconnected, every visible **Fader** dial and **Auto-fade** key shows the same one-line connection status reason. |

## 5. `API-CONTRACT.md` Vendor API Compliance (`R-API-*`)

| ID | Requirement |
|---|---|
| `R-API-1` | **Strict Adherence to `API-CONTRACT.md`:** All communication with Midi Fadester uses `CallVendorRequest` and `VendorEvent` with `vendorName: "midi-fadester"`. Continuous values are floats in `[0.0, 1.0]`. Slot IDs are stable strings (`"crossfader"`, `"fader_1"` .. `"fader_8"`, `"master"`), never display names. |
| `R-API-2` | **Full Request Coverage:** The client implements and unit-tests all 6 requests in `API-CONTRACT.md`:<br>1. `get_state` (`{}` → `{ version, api_version?, studio_mode, device: { name, connected, error }, slots: FadesterSlot[] }`) — called immediately on connect and after any request error.<br>2. `set_fader_value` (`{ slot, value, release? }` → `{ slot, value }`) — moves a slot (`0.0..1.0`); `release: true` finishes a Studio Mode T-bar transition.<br>3. `nudge_fader` (`{ slot, delta }` → `{ slot, value }`) — adds signed `delta` for rotary dials, clamped to `0.0..1.0`.<br>4. `auto_fade` (`{ slot, to, ms }` → `{ slot }`) — runs a timed fade (`ms` in `50..20000`); replaces any running fade on that slot.<br>5. `set_slot` (`{ slot, target_mode?, source_a?, source_b?, curve?, afv? }` → updated `FadesterSlot`).<br>6. `load_profile` (`{ name }` → `{ loaded }`, e.g. `"apc40mk2"`). |
| `R-API-3` | **Vendor Event Subscription (`fader_changed` & `state_changed`):**<br>• `fader_changed` (`{ slot, value, origin }` where `origin` is `"midi" | "ui" | "api" | "auto_fade"`): updates the slot's cached `value` and triggers an event-driven redraw on every visible dial or key bound to `slot`, keeping the APC40 mkII and Stream Deck + in lockstep.<br>• `state_changed` (full `get_state` payload): updates `studio_mode`, `device`, and all `slots`, refreshes all visible dials and keys, and pushes updated slot dropdown items to any open Property Inspector. |
| `R-API-4` | **Two-Layer Error Handling & Post-Error State Resync:**<br>• **Transport-level errors:** When `CallVendorRequest` returns `requestStatus.result === false` (e.g. code `600` when `midi-fadester` is not loaded), handle via `requestStatus.code` and `requestStatus.comment`.<br>• **Vendor-level validation errors (`API-CONTRACT.md` lines 52–54):** When `responseData` contains `{ error: string, comment: string }` (e.g., `"Slot 'fader_9' does not exist. Valid slots: crossfader, fader_1 .. fader_8, master."`), surface `comment` directly to the user without guessing, and immediately call `get_state` to resync local state (`API-CONTRACT.md`: *"Surfaces call it on connect and after any error."*). |
| `R-API-5` | **Contract Version Check:** Inspect `api_version` (when present in `get_state`, starting at `1`). If `api_version > 1`, display a clear version-mismatch sentence instructing the user to update Fadester for OBS. |

## 6. Launch Actions (`R-ACT-*`, Phase 1 Scope)

Only two actions are included in the Phase 1 launch set. Standard OBS scene switching and Studio Mode toggles already exist in Elgato's OBS Studio plugin and MUST NOT be duplicated in Phase 1.

| ID | Phase | Requirement |
|---|---|---|
| `R-ACT-1` | **Phase 1** | **Action 1 — `Fader` (Rotary Dial / Encoder on Stream Deck +):**<br>• **UUID:** `com.jbrick2070.fadester-for-obs.fader` (`Controllers: ["Encoder"]`).<br>• **Zero-Typing Default:** Dropping **Fader** onto a dial defaults `slot` to `"crossfader"`, `stepPerTick` to `0.02` (`2%`), `acceleration` to `true`, `pressAction` to `"snap_0_100"`, `longPressAction` to `"auto_fade_3s"`, and `showThumbnails` to `true` (active when the bound slot is in `crossfade_ab` mode).<br>• **Property Inspector Settings:**<br>  1. **Slot:** Live dropdown populated from `get_state.slots`, showing each slot's `name`, `label`, and when `available === false`, its `reason` (e.g., `Crossfader — Studio Mode is off`).<br>  2. **Step per tick:** `1%` (`0.01`), `2%` (`0.02`, default), or `5%` (`0.05`).<br>  3. **Acceleration:** Checkbox, **on by default (`true`)**. Fast turns scale the step multiplier (`1×` at `|ticks| == 1` and interval `> 60 ms`; `2×` for moderate speed; `3×` for rapid turns) so a slow turn gives fine `1–2%` trim and a quick flick sweeps `0 → 100%`.<br>  4. **Press Action:** `Snap 0/100` (default), `Auto-fade 1 s`, `Auto-fade 2 s`, `Cut`, or `Finish T-bar`.<br>  5. **Long Press (`D-3`, `800 ms` Hold with Visual Hold Indicator):** Holding the dial for **`>= 800 ms`** triggers `Auto-fade 3 s` (`ms: 3000`; configurable to `Auto-fade 3 s` or `None`). While the dial is held down prior to `800 ms`, the cell renders a bold orange **Hold indicator (`HOLD 3s FADE`)** so a timed fade never starts by surprise during a show.<br>  6. **Live Thumbnails (Crossfade mode):** Checkbox, **on by default (`true`)**, enabling `96 × 54` `GetSourceScreenshot` previews at 1–2 FPS when `target_mode === "crossfade_ab"`.<br>• **Hardware Events:**<br>  – `onDialRotate`: Calls `nudge_fader({ slot, delta })` with accelerated `delta`.<br>  – `onDialDown` / `onDialUp`: On `onDialDown`, arms the `800 ms` hold timer and draws the cell's Hold indicator. Releasing before `800 ms` (`onDialUp`) clears the Hold indicator and runs the selected short Press action (`set_fader_value` with `release: true` for `Snap 0/100`, `Cut`, and `Finish T-bar`; `auto_fade` with `ms: 1000` or `2000` for `Auto-fade 1 s` / `2 s`). Holding to `800 ms` clears the Hold indicator and fires `auto_fade` (`ms: 3000`). Target rail for toggle actions is `1.0` when `value < 0.5` and `0.0` when `value >= 0.5` (`Finish T-bar` always targets `1.0` with `release: true`).<br>  – `onTouchTap`: Reads `ev.payload.tapPos[0]` (`x` in `0..200`), maps `x` with `20 px` rail snap zones (`x <= 20 → 0.0`, `x >= 180 → 1.0`, linear `(x - 20) / 160` in between; in `tbar` mode, tapping completes the throw or jumps to position), and calls `set_fader_value({ slot, value, release: value === 0 || value === 1 })`. |
| `R-ACT-2` | **Phase 1** | **Action 2 — `Auto-fade` (Keypad Button):**<br>• **UUID:** `com.jbrick2070.fadester-for-obs.auto-fade` (`Controllers: ["Keypad"]`).<br>• **Default Settings:** `slot: "crossfader"`, `to: 1.0` (`100%`), `durationMs: 1000` (`1.0 s`).<br>• **Property Inspector Settings:**<br>  1. **Slot:** Live dropdown populated from `get_state.slots` (with `label` and `reason`).<br>  2. **To:** `0%` (`0.0`) or `100%` (`1.0`).<br>  3. **Duration:** Selectable duration in seconds / milliseconds (`50..20000 ms`, presets `0.25 s`, `0.5 s`, `1 s`, `2 s`, `3 s`, `5 s` + custom ms input).<br>• **Hardware Events & Live Key Display:**<br>  – `onKeyDown`: Calls `auto_fade({ slot, to, ms: durationMs })`.<br>  – **Key Canvas (`120 × 120` SVG):** Renders the slot's live percent (`0%`–`100%`), target badge (`→ 100%` or `→ 0%`), and a Playlister-styled blue-to-violet progress bar, or the one-line reason when unassigned, unavailable, or disconnected. |
| `R-ACT-3` | **0.7.7** | **OBS Scene Info Bar (Stream Deck Neo Info Bar, display only):** UUID `com.jbrick2070.fadester-for-obs.obs-neo-infobar`, `Controllers: ["Neo"]`, layout `layouts/obs-neo-infobar.json` (232 x 50). Shows the shared OBS connection's status, the live scene and, in Studio Mode, the preview scene ("Studio Mode off" otherwise); updates on connection and scene events, at most every 100 ms. When Studio Mode turns on, the previous preview value is cleared and the catalog re-read, so a stale preview is never shown. | `R-PLT-4` | **Per-UUID serial transport:** at most four discrete commands per UUID including the one in flight; a fifth press is busy and sends nothing. Nothing is sent when unbound, unavailable, unsupported, disconnected or during a collection change. |
| `R-PLT-5` | **Toggle from fresh state:** Play/Pause reads the state inside the queue: PLAYING sends PAUSE; PAUSED, STOPPED, ENDED and NONE send PLAY (native: STOPPED reloads the current item, ENDED starts the first playable row, NONE may stay idle); OPENING and BUFFERING keep an existing pending intent and infer no new direction; ERROR and unmapped states refuse the toggle while Stop stays available. A press while an intent is pending is rejected without a request. PLAY releases its pending mark after the post-command read; PAUSE may wait up to 20 s, cleared by PAUSED, STOPPED, ENDED, NONE, ERROR, an explicit Stop, Next, Previous or Restart, or lifecycle invalidation; at expiry the key says "sent; state unconfirmed", never failure. |
